Fortified Enterprise Fleet · All Things Agentic Hackathon · three ADK agents on Google Cloud

Sanctions screening for the people Firco won’t sell to.

Amara runs grants at a 12-person humanitarian NGO. The morning Treasury updates the OFAC SDN list, every queued disbursement in her book becomes her personal federal liability — the same strict-liability statute that binds a bank, with zero compliance department behind her.

Firco, LexisNexis, and ComplyAdvantage sell this problem to banks at $30k+/yr — and won’t sell to her at any price. Interdict is the compliance department she doesn’t have: an autonomous agent fleet that does the re-screen, stops the money, writes the rationale, and drafts the statutory report — unattended.

Every decision it makes is graded against oracles we don’t control, and every number on this page traces to a public Treasury artifact or a hash committed to git. You can reproduce all of it.

The one flow — nothing else

OFAC publishes. Interdict acts. Nobody clicks.

One narrow flow, end to end, with money consequences in both directions.

  1. Delta landsCloud Scheduler polls OFAC’s delta feed every 6 hours; each entry carries an explicit add / remove action.
  2. Full-book re-screenEvery counterparty, checkpointed and crash-safe — a silently skipped row is a compliance breach.
  3. True hits HELDMoney stops. An idempotent hold lands on the counterparty and every queued disbursement to it.
  4. Lookalikes CLEAREDWith a written rationale: weak-alias downweighting per OFAC’s own guidance, DOB corroboration from the feed’s own flags.
  5. Funds RELEASEDA delisting delta autonomously releases blocked funds and retires the hold.
  6. Report draftedThe OFAC blocking report, against the real 10-business-day statutory clock, filed to an append-only ledger.

Transmission of the report to OFAC stays human — stated honestly, everywhere.

Autonomy you can audit

Four decisions, no human click, each graded externally

An agent that acts on money has to be checkable by someone other than its builder. Every decision has an external grader.

DecisionWhat movesExternal grader
HOLD — adjudicated true hit Money stops: idempotent hold on the counterparty and every queued disbursement Judge cross-checks the SDN record (name / DOB / passport) on treasury.gov; make challenge reproduces it on any name
CLEAR — lookalike auto-cleared Disbursement proceeds, with a written rationale citing fields that actually exist in the record Agreement table vs OpenSanctions yente and OFAC’s own Sanctions List Search — whole book, every day

REPORT — statutory artifact Blocking report drafted against the 10-business-day clock, deadline tracked in the ledger Report fields verify against the public SDN record

Architecture

Three agents, two planes, one guard that decides what executes

The deterministic matching plane is the oracle for the LLM plane. Because the planes are separate ADK agents, that check is literal inter-agent routing — not a function call inside a monolith. Deterministic code decides what executes; the LLM explains and judges.

orchestrator ADK · Cloud Run · thin oracle guard

Routes matcher → adjudicator and applies the guard on every hop. Exposes screen_counterparty as the A2A-cataloged skill. Owns quarantine.

  • Oracle disagreement: a CLEAR against a deterministic score ≥ 0.93, or a HOLD below the 0.62 no-hit floor with no corroborating citation, quarantines instead of executing.
  • Citation check: every cited field must exist verbatim in the actual records — a hallucinated passport number is a schema rejection, not a hold.
  • Loop cap: hard cap of 2 matcher↔adjudicator round-trips per (hit, list_version), counted in Postgres — a looping worker cannot out-vote the router; it terminates in a quarantine terminal state.
  • Fail-closed: while quarantined, the disbursement stays held. A confused agent can never move money.

matcher-agent deterministic plane · no LLM

Normalization, Jaro-Winkler + transliteration scoring, weak-alias handling, checkpointed full-book re-screen. Always right about arithmetic. Pure functions, testable to exhaustion.

adjudicator-agent Gemini plane · structured output

Writes every hold/clear rationale as strict structured output: verdict, confidence, cited fields. DOB corroboration and weak-alias downweighting per OFAC’s own published guidance.

the money plane Postgres — where correctness actually lives

The orchestrator is the sole writer of decisions, and every one lands in constraints rather than in application code: idempotent holds under UNIQUE … NULLS NOT DISTINCT, an illegal-transition trigger so screened money cannot skip states, and a hash-chained append-only ledger whose sequence is assigned inside the chaining lock — so the audit trail cannot fork, and cannot be rewritten even by us.

This is the direct, structural answer to the track’s failure-tolerance question — how does the system recover if a worker agent loops or returns a hallucination? — answered by the router itself, not by a paragraph in a README.

The anti-plant proof

The sentinel book: a release demo nobody could stage

The easy way to demo “releases funds on delisting” is to pre-seed a name you already know was removed and replay the delta. Hindsight — and rightly discounted. We did the opposite.

The counterparty book contains 400 sentinels drawn from entries on the SDN list at seal time, committed with their SHA-256 before any later OFAC publication existed. If OFAC subsequently removes anyone in this book, the release leg fires on an entry nobody could have known would be delisted — and git log proves the book predates the removal.

StratumRowsSelection rule
SDNTK (counter-narcotics)250lowest 250 by sha256("interdict-sentinel-v1:" + uid) among SDNTK entries

Remainder of the list50same rule across everything not already claimed

Why weighted, and why that isn’t cherry-picking. Measured across every OFAC publication from 2026-06-26 to 08-07: 396 removals in 7 publications, heavily concentrated in a few programs (SDNTK carries 4.5× its share of removals, IRAQ2 13×). Stratifying the same 400 rows lifts quiet-window firing probability from ~28% to ~88%. The weighting is on program membership — public and fixed at seal time. Which entries OFAC will remove stays unknowable; within every stratum, ordering is by SHA-256 of the entry id. Deterministic, no RNG, no name chosen by hand — and re-runnable by anyone.

Honesty as a feature

What’s synthetic is labelled. What’s real is reproducible.

Stated plainly

  • The counterparty ledger is synthetic and labelled on screen the moment it appears. Real Treasury data triggers the system; real public records back the book; no actual NGO’s payment ledger is involved.
  • Sentinels are labelled sentinel: true in-product and disclosed in the README. They exist to catch real delistings — saying so is the point.
  • If no sentinel fires before the deadline, the demo falls back to a clearly labelled replay of the real 2026-08-07 removals with OFAC’s Recent Actions page and the Federal Register notice on screen. Never presented as live.
  • Report transmission to OFAC stays human. The agent drafts and tracks the deadline; it does not file with the government.

Reproduce it yourself

The dev loop and the judge’s verification path are the same commands.

# Adjudicate ANY name the system has never seen — your pick, not our fixture
make challenge NAME='Wladimir Wladimirowitsch Putin'

# Clean-machine path: seed from fixtures, verify the book hash, fetch the
# current real OFAC list, run the full flow, print the oracle agreement table
make reproduce
# Verify the sentinel book was not planted — re-derive it from the pinned snapshot
curl -sSL -o data/SDN.XML \
  "https://sanctionslistservice.ofac.treas.gov/api/PublicationPreview/exports/SDN.XML"
shasum -a 256 data/SDN.XML          # snapshot: ac00228a68345e5c0d7174713cf97e5d…
python3 scripts/seed_sentinels.py --sdn data/SDN.XML --out data/sentinels.csv
shasum -a 256 data/sentinels.csv    # book:     66eb151cc7473024ed3f9fb4f43700ed…

Note: re-running against a later SDN snapshot will not reproduce the book hash, by design — entries added or removed since 08/07/2026 change the eligible pool. That’s why the snapshot hash is recorded alongside the book hash.

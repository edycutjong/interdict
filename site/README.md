# site/ — judge-facing web surfaces

Two self-contained HTML files. No build step, no dependencies, no server required.

| File | What it is | Open it |
|---|---|---|
| `index.html` | Landing page — the 60-second case: the operator, the loop, the verified proof, the reproduce commands | double-click, or serve the folder |
| `pitch-deck.html` | 10-slide pitch deck — arrow/space to navigate, `ESC` overview grid, `P` presenter notes, `C` contrast check, print-to-PDF at 16×9 landscape | double-click |

Both open directly from `file://`.

## Serving locally

```bash
python3 -m http.server 8000 --directory site
# -> http://localhost:8000
```

## GitHub Pages

⚠️ **Pages does not serve `/site` without configuration.** It natively supports only the repository
root or `/docs`. Pick one:

- **Rename this folder to `docs/`** — zero config, Pages picks it up from *Settings → Pages →
  Source: main /docs*.
- **Or add a Pages workflow** that uploads `site/` as the artifact.

## Regenerating

These are copies. The editable originals live in the project kitchen at `../../assets/` and are
regenerated by `/generate-assets` and `/generate-pitch-deck`. Edit there, then re-copy — do not
hand-edit these files, or the next regeneration will silently overwrite your changes.

## Before the repo goes public

- `pitch-deck.html` slide 10 carries a **contact email** by design (the deck contract puts contact on
  the closing slide). Confirm you want it public, or strip it during the pre-flip scan.
- Both files contain placeholder blocks marked with `TODO` / `SWAP` comments where real screenshots
  go — architecture diagram, oracle agreement output, Cloud Scheduler run history, evidence console.
  Swap those before submission; they are deliberately not fabricated.
